# Local Test Control API

A dev/test surface for driving the E2E harness over HTTP. It is not a product
API, it is not started by the product, and it is not reachable from another
machine.

Implements the surface frozen in [`POST_MVP_TEST_PHASE.md`](../POST_MVP_TEST_PHASE.md)
against the contracts in `local_ai_stack.test_contracts`. It lives entirely in
`src/local_ai_stack/test_api/` and adds no dependency: the server is
`http.server` from the standard library.

## Starting it

```
set PEPITOS_AI_HUB_TEST_TOKEN=<43+ characters>
python -m local_ai_stack.test_api --profile pepe
```

The token comes from `PEPITOS_AI_HUB_TEST_TOKEN`, or from a file named by
`PEPITOS_AI_HUB_TEST_TOKEN_FILE`. There is no default and no generated
fallback: without a token the server exits. It is never passed as an argument,
so it does not reach shell history or a process listing, and it is never
printed.

Every capability beyond reading is off unless the command line turns it on:
`--allow-real-providers`, `--allow-network`, `--allow-gpu`. A run that asks for
one the server was not started with is refused with `403 not-enabled`. This is
what keeps "real providers are separately gated" a property of the deployment
rather than a promise about request bodies.

`--host` accepts a literal loopback address and nothing else. `0.0.0.0`, a LAN
address and the name `localhost` are all refused before a socket exists. There
is no override. Remote use belongs behind an authenticated tunnel that
terminates on this machine.

## Routes

All under `/internal/test/v1`, all requiring `Authorization: Bearer <token>`,
health included.

| Method and path | Purpose |
|---|---|
| `GET /health` | The server is up. |
| `GET /status` | Sanitized aggregate state plus this server's runs. |
| `POST /runs` | Validate a run request, queue it, return `202`. |
| `GET /runs/{run_id}` | Run state, the harness report, and stream diagnostics. |
| `GET /runs/{run_id}/events` | The run's events as SSE. |

There is no `/plan`, `/start`, `/stop`, `/services`, `/models` or `/cleanup`. A
phase is submitted as a one-phase run; a second command surface would duplicate
validation and create a second authority.

Unknown routes answer `404` — but only once authenticated. Without a token
every path answers `401`, so the surface cannot be enumerated.

## Requesting a run

```json
{
  "profile_id": "pepe",
  "phases": ["preflight", "plan"],
  "root_mode": "ephemeral",
  "provider_mode": "controlled",
  "allow_network": false,
  "allow_gpu": false
}
```

Those six fields are the whole vocabulary, and they mirror `TestRunSpec`
exactly. There is no field for a command, an executable, an argument list, a
working directory, an environment variable, a filesystem path, a URL, a port, a
PID or a service id, so a request cannot ask for any of them. Unknown fields
are rejected rather than ignored, as are unknown enum values, a profile the
server was not told about, and a repeated phase.

Bodies are capped at 4 KiB, must be `application/json`, and must carry a
`Content-Length`. A refused body is not read.

Only one run may be queued or running at a time; a second `POST /runs` answers
`409 run-in-progress`. Reading is not serialized: status and event streams are
served concurrently while a run is in flight.

## Run identifiers

A run id is 32 hexadecimal characters generated by the server. It is matched
against that exact pattern on the way in and is never joined to a path, so
there is nothing in it to traverse. Anything else is `404`.

## Events

Events are the harness's, not the API's. The server assigns storage, ordering
and fan-out; it does not rewrite what an event means.

- `id` is the sequence, starting at 1 and assigned by the store rather than
  trusted from the producer;
- `event` is the `TestEventKind` value;
- `data` is the whole serialized event;
- `Last-Event-ID` resumes after that sequence;
- keep-alives are comment lines carrying no application state;
- exactly one `result` event ends a stream.

That last guarantee is the API's. If the harness emits a terminal event, it is
used. If the harness returns or raises without one, the server writes a
terminal event from the report so the stream always ends. Anything emitted
after the terminal event is dropped and counted in the run's diagnostics.

Retention is bounded: 32 runs, 512 events per run, 8 KiB of data per event.
Oversized event data is replaced by its size and long messages are truncated,
which is what keeps the stream from becoming a log dump. A `Last-Event-ID` that
has already left the buffer answers `409 events-expired` rather than silently
skipping a gap.

SSE is output only. There is no route that accepts a command over a stream.

## What the API cannot do

The package imports `test_contracts` and one address constant from `endpoints`,
and nothing else from the product. It does not import `subprocess`, `psutil`,
`shutil`, `ctypes`, `winreg` or any HTTP client, and it never imports the
harness implementation — only the `TestHarness` protocol. Tests assert this by
parsing the package rather than by reading its prose.

So the API cannot start a process, stop one, adopt an external one, write
configuration, download anything, or delete a model. It calls
`TestHarness.run` once per run and republishes what comes back. Ownership of
processes, paths, provisioning and runtime control stays where it already is.

## Status

`GET /status` reports the server, its run counts, the active run, and whatever
a `StatusSource` hands it under `system`, `gpu`, `services` and `models`. That
projection is sanitized here: filesystem paths and non-loopback URLs are
replaced, anything named like a secret is redacted, strings are truncated and
depth is capped. A loopback URL survives, because "where does this service
listen" is what status exists to answer.

No status source is wired in yet, so those four keys are empty. Connecting one
is cross-integration work.

## Not in this round

- No cancellation. `TestRunState` is `queued`, `running`, `passed`, `failed`;
  a cancelled state would be a change to the frozen contract, so it is a
  `NEEDS_DECISION` rather than an invention.
- No harness. `python -m local_ai_stack.test_api` starts with a placeholder
  that fails every run instead of pretending to pass one. Wiring the real
  harness is a one-line change once that branch lands.
- No tunnel, no Tailscale, no SSH. Deliberately out of scope.
